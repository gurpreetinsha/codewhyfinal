Defense-in-Depth Security Architecture

      

        

          Layer 1: Perimeter & Edge Defense (Vercel Edge Firewall)
          
Global Anycast L3/4 DDoS protection, WAF custom rate-limiting rules, malicious bot scoring, and edge-enforced HSTS and CSP headers before traffic reaches backend code.

        

        

          Layer 2: Application Firewall (CodeWhy Shield Middleware)
          
Sliding-window persistent rate limits backed by SQLite (10 req/min for scans/AI, 15 req/min for auth, 120 req/min general), payload size caps (1MB JSON, 12MB audio), content-type validation, and path traversal / null-byte sanitization.

        

        

          Layer 3: Identity & Access Control (GitHub OAuth 2.0 & Backend RBAC)
          
Cryptographically unguessable state parameter with HttpOnly SameSite=Lax cookie preventing CSRF login attacks. Enforced server-side roles (Admin, Reviewer, Developer) restricting sensitive APIs regardless of frontend client behavior.

        

        

          Layer 4: Data Protection & Credential Isolation
          
Multi-tenant repository isolation ensuring no cross-account access. GitHub tokens stored encrypted via Fernet AES-128; automated preflight redaction masks 15+ secret types before storage or transmission to external models.

        

        

          Layer 5: Graph Engine & Multilingual AI Services (Neo4j & Sarvam AI)
          
Role-guarded knowledge graph relationship traversal with defensive attack path reconstruction. Secure TLS 1.3 backend communication to Sarvam AI with zero customer code used for model training.

        1. Minimum GitHub Permissions Requested
        

          CodeWhy requests only the minimum GitHub OAuth scopes necessary to function:
          read:user (for user identification),
          user:email (for account lookup), and
          repo (for inspecting repository file trees and pull request diffs).
          We never request organization administrative, billing, or write permissions.
        

      

      

        2. Transparent External AI Processing Disclosure
        

          When using AI features (Ask Why, CodeWhy Sentinel, or PR Risk Reviewer), user questions and non-secret AST code excerpts are transmitted over encrypted TLS to our configured AI service (Sarvam AI / LLM).
          
Automated Secret Redaction: Prior to transmission, CodeWhy runs our static credential scanner over all code snippets, replacing API keys, JWTs, private keys, database passwords, and GitHub tokens with [REDACTED_SECRET] placeholders.
          
Zero Model Training: Code excerpts are processed statelessly in-memory for inference only and are not used to train or fine-tune public foundation models.
        

      

      

        3. Zero-Persistence Source Code Policy
        

          CodeWhy analyses code in volatile server process memory only. We do not store raw cloned git repositories or raw source file contents on persistent database disks. Restarting the application purges all in-memory code structures.
        

      

      

        4. User Disconnection & Immediate Data Purge
        

          Users have complete sovereignty over their data. Clicking "Disconnect GitHub Account" or invoking POST /api/auth/disconnect immediately wipes the encrypted GitHub token from the database and terminates all active sessions.
